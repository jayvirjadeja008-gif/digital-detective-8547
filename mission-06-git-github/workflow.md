# Task 6.1 — Basic Git workflow

| Git operation | What it does |
|---|---|
| Check repository status: `git status` | Shows modified, staged and untracked files and the active branch. |
| Stage selected changes: `git add` | Moves selected file changes into the staging area for the next commit. |
| Create a commit: `git commit` | Saves a snapshot of the staged changes in local repository history with a message. |
| View commit history: `git log` | Lists recent commits, including identifiers and commit messages. |

Staging selects and prepares changes, but does not permanently record them in history. Committing creates a local snapshot of exactly what is in the staging area.

# Task 6.2 — Branch and Pull Request

A branch is an independent line of development in a Git repository. It lets work proceed separately from the main branch. A Pull Request is a GitHub request to review and combine a branch's changes into another branch.

This Mission 6 branch is named `update-about`. It adds a “My Learning” section to the root README. Branches and Pull Requests are useful because people can develop, review and discuss separate changes before they become part of the main project.
